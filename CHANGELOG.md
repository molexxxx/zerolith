# Changelog

Every package in this repository is released together and carries the same version. Entries name the packages they touch; breaking changes before 1.0.0 are called out as such.

## 0.1.0-alpha.10

### Breaking changes

- `@zerolith/router`: `href()` throws `route_name_unknown` for a name the route table does not hold, where it returned the base path, so a JavaScript project cannot ship a link to the home page in place of a misspelled one; a TypeScript project saw the mistake at type-check time already. The error names the route given.
- `@zerolith/router`: the document head is applied as a whole on every commit. `createRouter` takes `head`, the fields every page starts from, as an object or as a function of the URL and the matched route's name, undefined for the fallback, so the not-found page can have a title of its own; a route's fields go over them one by one, and a field neither gives goes back to what the page loaded with, the title and description written in `index.html`. A route that left out a field had kept the previous page's value, and the fallback had kept the previous title.
- `@zerolith/router`: a link or a `navigate()` to the URL of the page shown keeps the page, as back and forward between its entries already did: no loader runs and no view renders, the history entry follows the link, and with `scroll` on the page moves to the hash or the top. Rendering the page again had lost its state, such as an open `<details>` or the focus. A navigation whose query differs is another page, and one to the URL shown while another navigation loads cancels that one. `navigate(url, { reload: true })` loads and renders the page shown again on purpose, as after a form's redirect back to it; a form's `navigate` option that passes the router's `navigate` through should pass `reload` with it.
- `zerolith`: the JSX types check the namespaces against the element, as RFC 0001 says they do, so TypeScript code that passed a value a namespace does not take fails to compile where it compiled before; the runtime is unchanged. `prop:` takes the type of the element's own property, or a signal of it, `on:` takes a handler of the DOM event with `currentTarget` typed as the element, so `event.currentTarget.value` reads on an input and fails on a div, `bool:` takes a boolean or a signal of one, and `ref` takes a function of the element or a writable signal. Every namespace had taken `unknown`. A plain attribute still takes any value, and an element TypeScript does not know, such as a custom element, takes any property, handler, and flag. `Bindable`, `Ref`, `EventHandler`, `PropertyAttributes`, `EventAttributes`, `BooleanAttributes`, `KnownElements`, and `AnyElementAttributes` are exported from `zerolith/jsx-runtime` for a component that forwards attributes.

### Changed

- `@zerolith/cli` and the `zerolith` crate: `zerolith importmap` and `zerolith build --unbundled` copy each package's `LICENSE` next to its `VERSION` file, since a site that commits and deploys `vendor/` redistributes the packages, and write `vendor/.gitattributes`, which turns line ending conversion off so a checkout on Windows does not fail the modules' integrity hashes, and `vendor/.gitignore`, which keeps the packages' `dist/` folders in commits whatever the project's own `dist/` rule says. A page gets its import map before its first module script, where it had gone before `</head>`, after a module script already there, which the browser then ignored the map for; a page with CRLF line endings keeps them, where every run had marked it changed; and the preload links are indented like the map line, where they had started at the margin.
- `@zerolith/cli` and the `zerolith` crate: `zerolith dev` and `serve` serve a module under a folder `zerolith importmap` wrote as it is, so the integrity hash the page's import map gives it holds; they had rewritten its imports as they rewrite the project's own, which failed the hash on every load.
- `@zerolith/cli` and the `zerolith` crate: `zerolith importmap --html` follows the page's module scripts, inline ones included, through their relative and root-relative imports, and maps and vendors the entries they import, statically or through `import()` of a literal or of a `const` holding one, with the modules those load; the entries the page does not reach, such as `zerolith/ssr` and `@zerolith/router/server` on a page rendered in the browser, are left out of the map, and a package it does not reach is left on disk as it is, for a page the run was not given. `--html` can be given once per page, which vendors what any of them reaches and writes each page's own tags. The preload links name the modules the page's entries load statically and the vendored modules they import, where they had named every module every entry of every package loads and none of the page's own. A page whose modules load another through an `import()` the command cannot follow, or that import nothing from the packages, gets every entry, as a run without `--html` does. `zerolith build --unbundled` vendors what its pages reach the same way and preloads each page's own modules.
- `@zerolith/cli` and the `zerolith` crate: `zerolith build --unbundled` copies a folder `zerolith importmap` wrote, which its `importmap.json` marks, as it is, apart from the zerolith packages and the `importmap.json` under the project's own `vendor/`, which it writes anew; it had left the whole `vendor/` folder out, so a package vendored by hand next to the zerolith ones, with its entry in the page's import map, was missing from the output. Its summary counts the modules written, the ones transformed from TypeScript or JSX among them, where it had counted only the transformed ones and reported none for a JavaScript project.
- `@zerolith/vite` and the `zerolith` crate: a production build fails when the development build of any zerolith package reaches the output, naming the package and the module; the check had matched only the core's `dist/`, so the inspector of `@zerolith/devtools`, which `development` maps to and `default` maps away from, could ship unreported through an alias or a `development` condition. A package published without a `dist/production/` folder is not reported.
- Docs: the templates guide says when a `ref` runs, at the element's creation and before its template is in the document, that each content binding is a text node of its own, which kerning does not cross, and how an effect drives markup the page already holds; the signals guide says when a resource's `params` run.
- Docs site: the first page hands its title and description to the router as its head, since the router now applies the head as a whole.
- Docs: the deploying guide's unbundled section and the command line guide's `importmap` section show `blocking="render"` on the entry module script, which holds a browser-rendered page's first paint until the application is in it, so the static shell no longer paints first and shifts; the browsers that honor it and the ones that ignore it are named.
- Repository: the scaffold check ends a project's command that runs past `SCAFFOLDS_TIMEOUT` seconds, 600 by default, with every process it started and fails the project with its log, where a test run that never exited had held the whole check.
- Fullstack example and `zerolith new --example fullstack`: Harbor's sign-in page navigates to the page shown with `reload`, so it loads for the signed-in session.

## 0.1.0-alpha.9 (2026-11-03)

Rows hold less memory: with 1,000 rows of the js-framework-benchmark entry, the page keeps about 11% less than with 0.1.0-alpha.8, both measured the same way on one machine, since a signal bound into a template no longer holds an effect function and its closure, a binding that is its element's only child adds no comment marker, and a row holds fewer objects and arrays. The core's production bundle is 10,315 B after gzip, 418 B more than 0.1.0-alpha.8's, and its budget grows to 10,752 B from 10,240 B to make room for this work. Each release is now measured on js-framework-benchmark once it is published, beside the release before in the same session, and https://zerolith.dev/benchmarks/ shows the results, this release's memory among them.

### Changed

- `zerolith`: a signal written into a template's content, as `${count}`, or as the whole value of an attribute or a property is bound by a reaction that holds the signal and the part it writes to, where it had been an effect whose function closed over both, so each such binding is one object in place of an effect, a closure, and the closure's scope. A row of the js-framework-benchmark entry holds two closures fewer, so 1,000 rows keep 126 KB less, as `performance.measureUserAgentSpecificMemory()` reports them after garbage collection, the medians of seven loads on one machine. A binding still tracks what writing its value reads, owns what that creates, and ends with its owner. `npm run bench:compare` measures appending 1,000 rows 6% faster than 0.1.0-alpha.8 and every other operation within 1.5% of it.
- `zerolith`: an owner keeps the effects, bindings, scopes, and `onDispose` callbacks it owns in a list that runs through them, where it kept an array, which V8 sizes for 17 entries on the first push, so a keyed row's owner, which holds a few, takes 79 B less, 79 KB for 1,000 rows. Disposal still runs newest first and reaches every child when one throws, and a child disposed with its owner lets go of the older ones, so a child still referenced elsewhere keeps none of them alive. `npm run bench:compare` measures every operation within 3.2% of the core before it.
- `zerolith`: a binding that is its element's only child, as `${label}` in `<a>${label}</a>`, adds no comment marker to the page. It shows text, or nothing, in the one text node its element holds, and adds its marker after that node only when it first shows a template, a list, a node, or raw markup. A row of the js-framework-benchmark entry now holds the nodes the vanilla entry's row holds, two comments fewer, so 1,000 rows keep 178 KB less, and `npm run bench:compare` measures creating and appending rows about 3% faster. Server-rendered markup keeps its markers, which hydration adopts as before, and rows the client adds afterward carry none.
- `zerolith`: a template instance with one top-level node, as a keyed row usually is, holds that node with no array around it, and so does the row `each` keeps for it, so 1,000 rows keep 26 KB less.
- `zerolith`: a binding on an element is a part of the class its kind needs, so the part of an attribute, a boolean attribute, or a property holds no listener or ref fields; 1,000 keyed rows with a bound class keep 16 KB less.
- `zerolith`: a row of `each` is also the owner of what its view creates, where it held a separate owner, so 1,000 rows keep 9 KB less.
- Each release is measured on js-framework-benchmark once it is published. The benchmarks workflow measures it next to hand-written JavaScript and the frameworks `benchmarks/frameworks.json` lists, along with the release before, built from that release's own entry files, in the same session on the same machine, and commits the run to `benchmarks/results/`, from which the benchmarks README and the docs site render their results. Memory, size, and first paint, which the benchmark samples once a pass, are the medians of five passes. The entry in `benchmarks/js-framework-benchmark/` is pinned to each release as its run lands.
- Docs site: a benchmarks page, https://zerolith.dev/benchmarks/, linked from the header and the home page, shows the newest release's run: each framework's score, ranked, with a bar for its extra time over the fastest framework at each operation and zerolith's release before ranked beside it, its bar outlined, when the run measured it; then each operation's median time, memory, size, and first paint, the scores of every run kept so far, and how the runs are measured. Its Markdown twin, `/benchmarks.md`, carries the results as the benchmarks README renders them.
- Docs site: the playground's async data example fetches each city's record, a JSON file the site serves beside the playground, where it had waited on a timer to stand in for a server, and aborts a request that a newer choice replaces; Atlantis, which has no record, fails with the server's own 404. The card shows the city's local time, ticking in the city's time zone, the time zone, the population with the year it was counted, the area, the density, the coordinates, the currency, the official languages, and the calling code, formatted for the reader's locale with `Intl`, and names its sources: Wikipedia and the official statistics it cites.
- Docs: the benchmarks README leads with the newest release's results, which `npm run bench:report` writes from the runs in `benchmarks/results/`, followed by every run's scores, where it had added each run below the earlier ones; the roadmap marks the per-row memory work done so far and names what remains.

### Fixed

- Docs site: a page exactly as tall as the window, as the playground is, no longer scrolls by 17 px. The screen reader announcer at the end of every page is visually hidden, but kept a paragraph's margins; it now has the -1 px margin of the visually hidden pattern. The playground also fills the window to its last 2 px, which it had taken off for the header's rule a second time.

## 0.1.0-alpha.8 (2026-11-02)

The production build of every browser package is minified one module at a time, with source maps that lead back to the TypeScript, so a page that loads the core, the router, and `@zerolith/a11y` through an import map transfers 18,953 B of their modules after gzip, where 0.1.0-alpha.7 sent 35,833 B. `zerolith importmap` vendors only the modules a page's entries load and reads their imports with the parser, so every one of them gets an integrity hash and a preload. The docs moved to https://zerolith.dev/, where every diagnostic now links its page.

### Changed

- The docs site moved to https://zerolith.dev/, the project's own domain. The GitHub Pages address, https://molexxxx.github.io/zerolith/, redirects there page for page, so the links earlier versions print keep working.
- `zerolith` and the `zerolith` crate: every diagnostic links its page under `https://zerolith.dev/e/`, and `DIAGNOSTIC_URL` changes with it.
- `@zerolith/cli` and the `zerolith` crate: the projects `zerolith new` writes link the guides at https://zerolith.dev/, and `zerolith.schema.json` has the `$id` `https://zerolith.dev/zerolith.schema.json`.
- Every npm package and the crate name https://zerolith.dev/ as their homepage.
- `zerolith`, `@zerolith/router`, `@zerolith/a11y`, `@zerolith/forms`, `@zerolith/client`, `@zerolith/i18n`, `@zerolith/devtools`, and `@zerolith/otel`: the production build, which an import map, a CDN, and Node load, is minified one module at a time under the same file names, and each module has a source map that leads back to its TypeScript source and embeds it, so the browser's developer tools still show the source. The readable build, with its doc comments, is the `development` condition, which Vite, Vitest, and `zerolith dev` select and `zerolith importmap --development` maps. A page that loads the core, the router, and the accessibility primitives from an import map transfers 19 KB of their modules after gzip, where 0.1.0-alpha.7 sent 36 KB. Bundlers and Node take the minified build as well, where they had readable code; to read zerolith's own code while debugging, use the source maps, which Node applies with `--enable-source-maps`, or the readable build through the `development` condition. The core's `dist/production/` no longer holds copies of `index.d.ts` and `ssr.d.ts`, which no export resolved. `npm run size` also holds the core's modules, as an import map loads them, to a budget of 14 KiB after gzip.
- `@zerolith/cli` and the `zerolith` crate: `zerolith importmap` and `zerolith build --unbundled` vendor the modules the mapped entries load, following their imports, where they had copied every file of each package's `dist/`, both builds and the declaration files included. A vendored module comes with the source map its closing comment names when it is copied as published and the map holds its sources, since `src/` is not vendored. Every package is read and checked before anything is written, so a run that a check stops leaves the vendored files the page uses as they were; then the files are written in place, and when `--html` moves the page to the new map in the same run, as `build --unbundled` does, files an earlier run left in a package's folder, which its `VERSION` file marks, that the entries no longer load are removed, along with the page map's entries that pointed at them. A module the entries name that the installed package does not hold, an entry or import that leaves its package's folder, and a package folder without a `VERSION` file stop the command, where the map had pointed at a missing file or the files had been merged in. A module that `import()` loads by a literal path is vendored with an integrity hash and no preload link.
- Docs site: wheel scrolling on a mouse or trackpad glides through Lenis 1.3.27, so a wheel step eases over about a quarter second instead of jumping, at the same pace on a 60 Hz or a 144 Hz display. Links to a heading on the same page glide there, or jump when it is more than two screens away, and keep their history entries; a navigation lands where the router puts it, with no glide left over. Touch and keyboard scrolling stay native, the sidebar, sideways code, and the search dialog keep their own scrolling, and under `prefers-reduced-motion` the scroller never loads.

### Fixed

- `@zerolith/cli` and the `zerolith` crate: `zerolith importmap` and `zerolith build --unbundled` read a module's imports with the parser, so a module imported only for its effects, as in `import "./x.js"`, and one a minifier wrote as `from"./x.js"` get an integrity hash and a preload link, which the text search had missed, and text that only looks like an import no longer counts. A vendored module that does not parse stops the command with its URL and where the parser stopped, where its imports had loaded unchecked. A module copied without its source map, such as one the template pass rewrote, loses the comment that named the map, so a browser asks for no map that is not there; an inline map stays with a module copied as published.

- `@zerolith/router`: `createRouter` reads its `base` in linear time; a long run of slashes inside the base made it quadratic.
- `@zerolith/client`: a call fills a route's path in linear time; a long run of `{` in the path made it quadratic.
- `@zerolith/client`: `zerolith-client` and `generateClient` write the document's title and version into the generated module's header comment on one line; a title or version holding a line break ended the comment, and what followed it became code in the module.
- `@zerolith/i18n`: generated modules write every string, select key, and locale with `<`, `>`, U+2028, and U+2029 escaped, so no message can end an inline script or open a comment, the index quotes each locale in its import paths, and a source name with a line break or a `<` stays inside the header comment.

## 0.1.0-alpha.7 (2026-11-01)

A schema named like a built-in type keeps its name in the typed client again, as in 0.1.0-alpha.5, unless the generated module writes that built-in; 0.1.0-alpha.6 renamed every such schema. Harbor, the fullstack example, now waits for its backend, so `npm run dev` and `npm run api` start in either order. Canaries are versioned below every release, and this release sorts above the 0.1.0-alpha.6 canary that sorted above 0.1.0-alpha.6.

### Breaking changes

- `@zerolith/client`: `zerolith-client` and `generateClient` keep a schema named like a built-in type under its own name again, as 0.1.0-alpha.5 did, unless the generated module writes that built-in, as it writes `Record` for an object of free keys and `Blob` for a binary response; 0.1.0-alpha.6 wrote every such schema under a numbered name, as `Record2`, which broke imports of the schema's type in modules that never wrote the built-in. Code written against 0.1.0-alpha.6's numbered name imports the schema's own name again. A schema that another schema's name, the interface, or `RouteTable` would clash with keeps its numbered name.

### Changed

- Canaries are versioned `0.0.0-canary.<yyyymmdd>.g<commit>`, which sorts below every release, so no range that names a release, such as `^0.1.0-alpha.6`, matches one, and only `@canary` installs it. They had been the current version with a canary prerelease after it, as `0.1.0-alpha.6.canary.20261101.g301d419`, which sorts after `0.1.0-alpha.6`, so a package manager that takes the highest match for `^0.1.0-alpha.6` could install that canary in place of the release.

### Fixed

- Fullstack example and `zerolith new --example fullstack`: while the backend does not answer, Harbor says so and asks for the session again every two seconds, opening as soon as it answers, so `npm run dev` started before `npm run api` no longer leaves the page out of reach until a reload. The README and the command-line guide say the two run side by side in either order.

## 0.1.0-alpha.6 (2026-11-01)

Components can own their cleanups: `render`, `hydrate`, `renderToString`, and `@zerolith/test`'s `mount` take a function that returns the view and call it inside the root's owner, and a component's styles can live in a stylesheet of their own, imported with `?scoped`. In development, a warning that no listener hears is printed to the console. Every package, the command line, the docs site, and the examples were reviewed end to end for this release, so the fixes run long: among them, the Vite plugin and the command line are held to shared fixtures, and a dependency can no longer copy a file from outside `node_modules` into the build. `when` and `each` now refuse a function, and `@zerolith/otel` names a client span by its method, so check those before upgrading.

### Breaking changes

- `@zerolith/otel`: a client span is named by its method, as `GET`, where it had been named by its method and path, as `GET /notes/1`, which gave every note a span name of its own; the HTTP conventions name a client span by its method when no route template is known, and the path stays in `url.full`. A navigation span's `url.query` leaves out the `?` and is left out when the URL has no query.
- `zerolith`: `when` refuses a function as its condition with `when_condition_function`, where it had shown the first branch no matter what, since a function always counts as true. Pass a signal or a computed value, as `when(computed(() => items.get().length === 0), Empty)`.

### Added

- `zerolith`: `render`, `hydrate`, and `renderToString` take a function that returns the view, as `render(() => App(), "#app")`, and call it inside the root's owner, so the effects and `onDispose` cleanups a component registers end with the root. Called with the view itself, such a component ran before any owner existed and failed with `on_dispose_outside_scope`. A component that takes props, passed by name as `render(Counter, "#app")`, fails with `mount_component_uncalled`, which names it, rather than running without them. The form works under the Vite plugin too, whose hot replacement now calls every recorded root inside its owner, and the starter's entry and the examples mount their layout this way.
- `zerolith`: in the development build, a warning, deprecation, or info diagnostic that no `onDiagnostic` listener hears is printed to the console, worded as an error's message is, so a hydration mismatch or a blocked URL no longer passes unseen; registering any listener takes them over, and the production build prints nothing.
- `zerolith`, `@zerolith/cli`, `@zerolith/vite`, and the `zerolith` crate: a component's styles can live in a stylesheet of their own, imported with `?scoped`, as `import card from "./card.css?scoped"`. The import gives the same `Styles` a `css` literal returns, scoped by the same `@scope` rule, and works under `zerolith dev`, `zerolith build`, `zerolith build --unbundled`, Vite with the plugin, and Vitest with the plugin. Local `@import`s are inlined and scoped with the rest, `url()` references resolve against the stylesheet, and the production build lowers and minifies the file like the project's other CSS; a remote `@import` is refused, since an adopted stylesheet cannot load one. The scope class holds the file's name and a hash of its path, so it stays the same while the file changes, and the server and the browser agree on it however each processed the file: an edit replaces the rules in place under both `zerolith dev` and Vite, with no reload. `zerolith/imports` types the import, and a plain `import "./print.css"` as well, which TypeScript 7 rejects without a declaration; the starter's `src/env.d.ts` references it. Harbor keeps its project board's styles in `project.css` this way.
- `@zerolith/vite`: a `hot` option, `true` by default; `false` leaves out the rewrite for hot module replacement, as a test runner wants, while JSX, `?scoped` stylesheets, and the warnings stay.
- `@zerolith/test`: `mount` takes a function that returns the view, as `mount(() => Dashboard())`, and hands it to `render`, which calls it inside the root's owner, so a component that registers cleanups with `onDispose` mounts as it is, and its cleanups run when the test unmounts it. Called with the view itself, such a component ran before any owner existed and failed with `on_dispose_outside_scope`.
- `@zerolith/router`: `observe` receives a `cancel` event for a navigation that a newer one replaced before it committed, so every `start` has an end. `@zerolith/otel` ends that navigation's span with `zerolith.navigation.canceled` and no error status.

### Changed

- `@zerolith/i18n`: a compiled message whose formatting options are all literals, such as `{$price :currency currency=EUR}`, uses a formatter created once per module and shared by every message that formats the same way, where each call had built and serialized its options to find a cached formatter; and a compiled module writes only the helpers its messages use, so a linter that checks the generated files finds no unused functions.
- `@zerolith/cli` and the `zerolith` crate: every starter's `vitest.config.ts` adds the zerolith plugin with `hot: false`, so tests read JSX and `?scoped` stylesheets as the app does, and every starter lists `@zerolith/vite` among its development dependencies; the fullstack example adds the plugin to its browser tests. The starter's README says the app itself needs no Vite, the plugin being there for the tests, and its layout names `src/env.d.ts` and `vitest.config.ts`.

A `head` that threw, such as one reading a field of a record the loader did not find, had left the URL changed, the old page shown, `pending` true for good, and an `observe` span with no end.
- `@zerolith/router`: `navigate` leaves a URL on another origin to the browser, with `location.assign`, or `location.replace` with `replace`. It had matched the URL's path against the local routes, run that route's loader, and then failed in `pushState`, which a form that follows a redirect to a sign-in page on another origin reached.
- `@zerolith/router`: a navigation aborts the loader of the one it replaces wherever it goes, an unmatched path included, so the `cancel` event arrives when it is replaced. Only a navigation to a matched route had aborted it.
- `@zerolith/router`: the first navigation of a fresh visit leaves the scroll position alone, where it had scrolled a server-rendered page back to the top once the loader resolved, under a reader who had already started scrolling.
- `zerolith`: a `resource` is a signal of its value, as its type and the signals guide say, so `${user}` in a template, `when(user, ...)`, and `each` read it like any other signal. It had been a plain object with a `get` method: binding it threw `unrenderable_value`, and `when` always showed its first branch.
- `zerolith`: a property binding to a URL property, such as `.href`, `.src`, `.action`, `.formAction`, or `.poster`, refuses a `javascript:` or `vbscript:` URL, or a `data:` URL that is not an image, and reports `unsafe_url_blocked`, as the attribute binding does. It had assigned the value, so a user-supplied link bound as a property could run script in the page.
- `zerolith`: the URL check reads only the start of a URL. It had copied the whole value on every write, so a `data:` image of a few megabytes, such as a photo preview from `FileReader`, blocked the page for a quarter of a second on each update, in the browser and on the server.
- `zerolith`: a ref signal keeps its element, and a ref callback is set up again after its cleanups run, when a signal applies the same template again; the ref had been reset to `undefined` while the element stayed on the page.
- `zerolith`: hydrating an empty string reports no mismatch. The server renders nothing for it, and hydration had counted the missing text node as a `hydration_mismatch` on every correct page with an empty field or message.
- `zerolith`: an element registered with `define` runs its view inside the element's root, so the effects and `onDispose` cleanups the view registers end when the element disconnects, where an effect had kept running and `onDispose` had thrown `on_dispose_outside_scope`. An element created or moved on the client renders without reporting a `hydration_mismatch`; it hydrates only when it holds server-rendered markup, as the elements guide says.
- `zerolith`: a cleanup that throws no longer stops the rest of a disposal. Every other effect, scope, and cleanup of the owner is still disposed, the effect's own cleanup still runs, and the first error is thrown once they are done. One throwing `onDispose` had left its sibling effects subscribed, updating detached nodes and holding their listeners and timers.
- `@zerolith/cli` and the `zerolith` crate: `zerolith build --sourcemap` maps the modules that hold a template or JSX back to their source, and no longer warns once per module that the map is likely incorrect. The build rewrote those modules without telling Rolldown that the rewrite keeps every line, so their maps were empty.
- `@zerolith/cli` and the `zerolith` crate: a build that cannot read a file names it. A `?raw` or `?scoped` import of a file that is not UTF-8, a stylesheet it imports, or a source of the unbundled output failed with the bare reason, such as "stream did not contain valid UTF-8", since the build shows its own failure messages in place of Rolldown's.
- `@zerolith/vite`, `@zerolith/cli`, and the `zerolith` crate: template lint findings point at the right place in a file with Windows line endings, and `zerolith doctor` no longer panics when a finding lands after a carriage return and a character of more than one byte. Both lints counted in the parser's raw template text, which turns `\r\n` into `\n`, so each carriage return moved a finding one place earlier.
- `zerolith`: a hydrated template that a signal applies again with the same strings updates as a client template. It kept the server cursors of its first pass and compared every later value with the live page as if it were server markup, so each update reported a `hydration_mismatch` that never happened, to every diagnostic listener and as a console warning in development.
- `zerolith`: hydration renders every row of a list whose server markup holds none of them, such as an `each` hydrated over the "Loading" branch the server rendered for an empty list, or an array hydrated over server text. The repair created the rows and then removed them with the server nodes it discarded, so the list showed nothing and later updates reached only the rows added after hydration.
- `@zerolith/cli` and the `zerolith` crate: `zerolith importmap` and `zerolith build --unbundled` vendor `@zerolith/a11y` and `@zerolith/i18n` with the other zerolith packages, and keep the entries of the page's own import map, its `scopes` included, for the specifiers they do not vendor. Both replaced the page's map outright, so a library mapped by hand, or either of those packages, failed to load from the output. `--unbundled` also warns of a bare import, such as `lit`, that no import map entry covers, naming the module that imports it.
- `@zerolith/vite`, `@zerolith/cli`, and the `zerolith` crate: a self-closing JSX element other than a void one, such as `<div />` or an SVG `<path ... />`, is lowered with its end tag. Both lowerings wrote only the start tag, so the HTML parser nested every following sibling inside the element, and an icon of several SVG shapes drew only the first.
- `@zerolith/cli` and the `zerolith` crate: `zerolith build --unbundled` deleted whatever folder `--out` or `build.out` named, since it compared the folder to the project without resolving `..`: `--out ..` removed the project's parent folder with every sibling in it. It now applies the bundled build's rules, which both builds resolve against the file system first: a folder that holds the project, is in the public folder, or holds a source the page loads is refused, and one outside the project is emptied only with `--empty-out-dir`, which `--unbundled` now accepts.
- `@zerolith/cli` and the `zerolith` crate: `zerolith build --out public` is refused. It had emptied the public folder and then copied it onto itself.
- Fullstack example and `zerolith new --example fullstack`: Harbor's Node adapter answers 400 to a request the Fetch API cannot represent, such as one with a malformed `Host` header or the `TRACE` method, where building the `Request` threw and ended the process, and it writes an error the app throws to stderr before answering 500, where the error had vanished.
- `@zerolith/client`: the generator refuses an `additionalOperations` key that is not an HTTP method name, and writes every method as a quoted string. It had written the key into the generated module as it was, so a crafted document could make the module run code of its choosing when the application loaded it, since `zerolith dev`, `zerolith build`, and Vite strip types without checking them.
- `@zerolith/client`: a path parameter of `.` or `..` throws a `TypeError` that names it. The URL read such a segment as a step, so `PUT /users/{id}/role` with `id` set to `..` reached `/role`, with the client's headers and credentials.
- `@zerolith/cli` and the `zerolith` crate: `zerolith dev`, `serve`, and `preview` answer a request only when its `Host` header names `localhost`, a name under `.localhost`, an IP address, or a host that the new `allowedHosts` setting in `zerolith.json` lists, and refuse any other with 403. A page on another site could point its own name at the loopback address and read the project's modules, its `PUBLIC_` variables, and the live edit stream; a name in the hosts file or a tunnel's address now goes in `allowedHosts`.
- `@zerolith/cli` and the `zerolith` crate: a request path with a `%` followed by a character outside ASCII no longer ends its connection with a panic, and an escape is read only as exactly two hex digits, so `%+5` stays as written.
- `@zerolith/cli` and the `zerolith` crate: `zerolith build` copies and hashes every local candidate of an `<img>` or `<source>` `srcset` and of a preload's `imagesrcset`, which it had left as written, so a responsive image's other sizes were missing from `dist/`.
- `@zerolith/cli` and the `zerolith` crate: the starter's stylesheet draws range sliders and progress bars square, in the control and text colors, where they had rendered as the browser's rounded widgets, and a disabled button keeps its disabled look under the pointer instead of taking the primary hover fill.
- `@zerolith/cli` and the `zerolith` crate: `zerolith build --unbundled` handles a module's imports of files that are not modules, as `zerolith dev` does, where it had copied them as written and the browser refused to load them: a stylesheet is linked from the page before the importer runs, a JSON file gives its value, an image, a font, or a file with `?url` its URL, and `?raw` a file's text, each through a small module the build writes next to the file. An import that names a file outside the project, such as `../../notes.txt?raw` from too far up, fails the build with the import that asked for it, rather than writing its module outside the output folder.
- `@zerolith/cli` and the `zerolith` crate: when `zerolith build` fails to read a file a module imports, such as a stylesheet with a syntax error, it reports the file and the reason instead of only naming the plugin that failed.
- `@zerolith/cli`: a release publishes `@zerolith/cli` only once every platform package downloads from the registry. A large platform package can take minutes to appear after it is published, and an install of `@zerolith/cli` in that time, such as through `npx`, skipped the binary and kept failing from npx's cache; the error for a missing binary now says how to clear that cache.
- `@zerolith/router`: scroll positions survive a reload. The router kept them in memory, so reloading a page returned to the top and, after a reload, back no longer returned to where the reader was on earlier pages; it now saves each position into its history entry's state when scrolling pauses and when the reader leaves the entry, and the browser keeps that state with the entry. A state that other code on the page stored in the entry is kept beside the position, and one that is not an object, such as a string, is replaced rather than spread into numbered keys.
- `@zerolith/router`: a navigation that a newer one replaced no longer calls `onError` when its loader rejects on the abort signal, as `fetch` does, which made an application that falls back to a full page load on error leave for the replaced URL. Back and forward between entries of the page shown that differ only in the hash move to the hash instead of loading and rendering the page again.
- Docs site: forms submit in the playground's preview, so the Add button of the Packing list example works. The preview's sandbox lacked `allow-forms`, which stops a form before its `submit` event fires.
- Docs site: the API reference, `api.json`, and `llms-full.txt` print every signature as the published types declare it. A parameter with a default value showed as `_` instead of its name and type, such as `createAnnouncer(_)` for `createAnnouncer(doc?: Document)`, template literal types carried terminal color codes in place of their backticks, interface methods lost their type parameters, the `~standard` property of `StandardSchema` lost its quotes, and the `JSX` namespace listed none of its members. The API reports in `api/` had the same faults and are now one TypeScript block each, which GitHub shows as code.
- Docs site: an example shows only the imports its code uses. A property that shares its name with an import, such as `messages.get()?.notesCount`, pulled that import into the example.
- Docs site: headings whose names differ only in case, such as the `signal` function and the `Signal` interface in the reference, get ids of their own (`#signal` and `#signal-2`), so each can be linked. They shared one id before, and a search that matched both stopped updating its results. The search index also no longer lists headings from inside code blocks, such as the sections of the `AGENTS.md` sample, which had no place on the page to land.

## 0.1.0-alpha.5 (2026-10-31)

The docs site is now a place to learn zerolith, with a home page that runs a counter, a ten-step tutorial, a playground, and a guide for coding agents, and every new project comes with the zerolith skill. `zerolith new --example fullstack` writes an app with its own Node backend, which `zerolith dev` reaches through a proxy under the app's base path, and keyed lists render in about half the script time of 0.1.0-alpha.4. The packages that share `zerolith/internal` now require the same version of zerolith, so upgrade them together.

### Breaking changes

- `zerolith`: the exports that only the build tools and the inspector use moved from `zerolith` to a new `zerolith/internal` entry, so the application API holds only what applications call. They are the template prepare pass (`prepared`, `scan`, `Scanned`, `PartSpec`, `PreparedPart`), the scope marker of scoped styles (`SCOPE_MARKER`), and the inspector hook (`devtoolsInternal`, `devtoolsSaveRestore`, `DevtoolsHook`, `DevtoolsEvent`, `NodeSnapshot`, `RootSnapshot`). Application code is unaffected. Upgrade `zerolith`, `@zerolith/vite`, `@zerolith/devtools`, and `@zerolith/cli` together: the 0.1.0-alpha.4 plugin, inspector, and command line import these names from `zerolith` and fail against this release.

- `@zerolith/cli` and the `zerolith` crate: `zerolith new` writes the zerolith skill for coding agents into `.agents/skills/zerolith/`, which Codex, Cursor, GitHub Copilot, Gemini CLI, and most other agents read, and `.claude/skills/zerolith/`, which Claude Code reads. Bodies stream both ways, server-sent events included; WebSocket connections are joined end to end; the backend receives its own `Host` with `X-Forwarded-Host`, `-Proto`, and `-For`; a redirect to the backend's own address comes back as a path; `stripPrefix` removes the matched prefix; and an unreachable backend answers 502 with the reason in the terminal. ### Breaking changes

- `zerolith`: `DIAGNOSTIC_URL`, and with it the link in every diagnostic, moves from `https://zerolith.dev/e/` to `https://molexxxx.github.io/zerolith/e/`, where the pages are published. The old address never resolved; the links move once more when the project registers its own domain.
- `@zerolith/vite`: `vite build` runs the template prepare pass by default, and a module that uses `html` from zerolith other than as a template tag, or re-exports it, fails the build at its line. `prepare: false` keeps the previous behavior.
- `@zerolith/cli` and the `zerolith` crate: `zerolith build` runs the same pass with the same refusals. `--no-prepare` keeps the previous behavior.

### Added

- `zerolith`: `render` and `hydrate` take a CSS selector for the container as well as an element, the root exposes the element it mounted into as `container`, and a selector that matches nothing reports `mount_target_missing`. The `@zerolith/vite` runtime and `tracedHydrate` in `@zerolith/otel` take the same targets.
- `zerolith`: `prepared` registers a template's scan made ahead of time, `scan` is exported for build tools, and `template_not_prepared` reports a template that a bundle without the scanner was never given.
- `@zerolith/vite`: the template prepare pass scans every `html` literal at build time, so the browser binds templates without scanning them and the scanner leaves the bundle.
- `@zerolith/cli` and the `zerolith` crate: `build` runs the prepare pass over the project's modules and the vendored packages and puts the scanner's stand-in in its place, held to the Vite plugin's output by a shared fixture.

### Fixed

- `@zerolith/cli` and the `zerolith` crate: `importmap` and `build` write each module's integrity hash on its preload link. Without it the browser could not use the preloads, because the import map gives the module requests that hash, and downloaded every vendored module twice. `doctor` warns about a page whose preload links lack it, under `preload_integrity_mismatch`.
- `@zerolith/cli` and the `zerolith` crate: `zerolith new` lists `@zerolith/test` and `@zerolith/vite` as development dependencies.
- `@zerolith/cli` and the `zerolith` crate: the usage text names the command `zerolith` on every platform instead of the executable file name.
- Every package: the `latest` dist-tag follows the newest pre-release until a stable version exists, so `npm install zerolith` no longer stays on `0.1.0-alpha.1`.

## 0.1.0-alpha.1 (2026-10-29)

The first published alpha. The API is not frozen: minor versions may change it until 1.0.0, and the `alpha` dist-tag marks that.

- `zerolith`: signals, `html` and `css` templates, fine-grained rendering, hydration, server rendering (`zerolith/ssr`), coded diagnostics with a catalog, custom elements (`zerolith/element`), the JSX types (`zerolith/jsx-runtime`), and the dev tools hook.
- `@zerolith/router`: the typed route table, loaders, head metadata, scroll restoration, the server entry (`@zerolith/router/server`) with embedded route data, and the `observe` hook.
- `@zerolith/forms`: native forms enhanced with `fetch`, RFC 9457 problem details with a `fields` map, and Standard Schema validation shared with the server.
- `@zerolith/client`: a typed client over a generated OpenAPI contract (`zerolith-client`), with a message port transport.
- `@zerolith/test`: mount with cleanup, settle, hydration mismatches, and accessibility issues.
- `@zerolith/a11y`: focus trap, roving tabindex, live announcer, focus origin, visually hidden styles, and media query signals.
- `@zerolith/i18n`: locale negotiation and state on `Intl`, formatters, and the MessageFormat 2 compiler (`zerolith-i18n`).
- `@zerolith/otel`: navigation, hydration, and request spans through `@opentelemetry/api`.
- `@zerolith/devtools`: the in-page inspector.
- `@zerolith/vite`: JSX lowering, hot replacement with named-signal restore, the production build check, and development warnings.
- `@zerolith/cli` and the `zerolith` crate: `dev` serving TypeScript and JSX through oxc, `build`, `importmap`, `doctor`, and `new`; npm installs a prebuilt binary through one optional platform package per target (Linux, macOS, and Windows on x64 and arm64).
